# 오늘의 스윙 — 글로벌 자금흐름 지도 + 다음 진행 로드맵

기준일: 2026-08-14

이 문서는 기존 `NEXT_RESEARCH_ROADMAP_2026-08-14.md`를 대체하지 않는다. 현재까지 끝난 연구를 바탕으로 **글로벌 섹터/지역 자금흐름 지도를 어디까지 활용할지**와 **기존 회전형 포트폴리오 연구를 어떤 순서로 이어갈지**를 고정한다.

## 핵심 원칙

1. Forward V1/V2는 계속 동결한다. 과거 연구 결과 때문에 수정하지 않는다.
2. Flow Map V1은 관찰용이다. 실제 펀드 순유입 데이터라고 부르지 않는다.
3. 새로운 기능이 생겨도 기존 핵심 연구인 자금회전·후보선택·위험배분을 뒤로 미루지 않는다.
4. 개발 데이터에서 좋아 보인 규칙은 Walk-forward를 통과하기 전까지 production이나 Forward V1/V2에 넣지 않는다.
5. 복잡한 점수 하나보다, 실제 계좌에서 자본이 어디에 묶이고 어떤 좋은 후보를 놓쳤는지를 우선 본다.

# A. 지금 계속 돌아가는 트랙 — Forward

## A1. Challenger V1

- 확인형 + SMA200/20 + Donchian
- frozen quality / priority calibration
- 거래당 계좌위험 1.00%
- 자연청산
- 최대 동시보유 10
- 자동 재튜닝 금지
- 실제 주문 OFF

## A2. Challenger V2

V1과 딱 하나만 다름.

- 거래당 계좌위험 0.75%

목적: 과거 rolling TEST에서 발견된 `1.00%보다 0.75%가 현금 고갈을 줄이고 다음 좋은 후보를 더 잡은 현상`이 실제 앞으로도 반복되는지 확인.

## A3. Forward 해석 규칙

- 30 closed trades 전: 규칙 변경 금지, 관찰 위주
- 30건 이후: 1차 formal review
- 50건 이후: 더 강한 비교 가능
- Forward 결과를 보고 같은 버전을 고치지 않는다. 변경이 필요하면 V3 등 새 Challenger로 분리한다.

## B3. Flow Proxy 점수

V1은 실제 ETF fund-flow 원자료가 아니라 다음 **가격·거래량 기반 proxy**를 사용한다.

- 35%: 5일 benchmark 대비 상대강도 순위
- 35%: 20일 benchmark 대비 상대강도 순위
- 15%: 상대강도 가속도 순위
- 15%: 최근 5일 / 20일 평균 거래량 비율 순위

절대 임계값을 미세조정하지 않고 동종 ETF 내부 percentile로 계산한다.

## B4. Rotation Map

- X축: 20일 benchmark 대비 상대강도
- Y축: 최근 상대강도 가속도

4구간:

- Leading: 강하고 더 강해짐
- Cooling: 강하지만 둔화
- Improving: 아직 약하지만 회복
- Lagging: 약하고 더 약해짐

## B5. 매우 중요한 제한

- Flow Map V1 자체는 매수/매도 신호가 아니다.
- 후보의 elite/priority에 아직 가점을 주지 않는다.
- 지역 ETF는 각 거래소의 최근 이용 가능한 종가를 사용하므로 완전히 같은 시각의 스냅샷은 아니다.
- 실제 펀드 설정/환매 기반 순유입 데이터가 아니므로 화면에도 `Flow Proxy`라고 명시한다.

# C. 기존 원래 연구 — 절대 놓치지 않을 다음 순서

## C1. 기회비용 회전 엔진 — NEXT PRIORITY

현재 가장 중요한 미완료 연구.

문제:

새로운 고품질 후보가 발생해도 기존 포지션에 자본이 묶여 현금부족으로 놓치는 경우가 많다.

핵심 질문:

> `큰 승자는 살려두면서, 돈만 묶고 있는 약한 포지션을 새 강한 후보와 교체하면 계좌 복리 회전이 좋아지는가?`

### 사전 등록할 거친 구조

과도한 grid search 금지. 몇 개의 논리적 구조만 비교한다.

- 기준: 기존 자연청산 유지
- 손실 교체형: 일정 최소 보유기간 이후 음수 R 포지션 중 가장 약한 포지션 1개만 교체
- 정체 교체형: 일정 최소 보유기간 이후 0R 이하이며 추세 진행이 없는 포지션 1개만 교체
- 승자 보호: +1R 이상 진행한 기존 포지션은 교체 대상에서 제외
- 새 후보는 해당 날짜의 우선순위 상위 후보만 교체를 요청할 수 있음

### 반드시 기록

- 교체 횟수
- 교체 때문에 새로 잡은 후보의 성과
- 팔아버린 기존 종목의 이후 MFE
- 잘못 팔아버린 대형 승자 수
- 현금부족 reject 감소
- fresh trades 증가
- 평균 보유기간
- 자금회전수
- 총수익 / MTM MDD
- 연도별 반복성

특히 `팔았던 종목이 나중에 크게 올랐는지`를 반드시 기록해야 한다.

## C2. 섹터·상관 집중 위험관리

기회비용 회전 엔진 뒤 진행.

예:

NVDA / AMD / AVGO / MU가 동시에 뜨는 것은 종목 4개지만 사실상 하나의 반도체 방향 베팅일 수 있다.

연구할 것:

- 같은 섹터 동시노출
- 동일 테마/고상관 종목 집중
- 섹터별 계좌 위험 합계
- 분산 때문에 수익을 희생하는지, MDD를 실질적으로 낮추는지

초기에는 단순 섹터 cap 몇 개만 사전 등록하고 촘촘한 최적화는 하지 않는다.

# D. Flow Map을 매매 엔진에 연결하는 순서

## D1. 관찰 로그부터

Flow Map 상태를 매 Market Scan마다 저장한다.

후보 발생 당시:

- 후보 전략
- 종목 섹터
- 섹터 flow score
- 섹터 quadrant
- 글로벌/미국 pulse

를 같이 보관할 수 있도록 확장한다.

단, V1 시각화 단계에서는 기존 추천/Forward 의사결정에 사용하지 않는다.

## D2. 역사적/Walk-forward 감사

질문:

- 강한 섹터의 Donchian 후보가 실제 TEST에서도 더 좋았는가?
- Improving 구간에서 먼저 들어가는 것이 유리했는가?
- 이미 Leading인 섹터는 오히려 과열돼 불리했는가?
- 섹터 flow는 후보 quality/priority와 중복된 정보인가, 새로운 정보인가?

검증해야 할 것:

- 거래당 R
- MFE/MAE
- top candidate hit rate
- portfolio return
- MTM MDD
- 현금부족 reject
- 연도별 방향 일치율

## D3. 연결 조건

Flow를 후보 우선순위에 넣으려면 최소한:

- 여러 rolling TEST에서 같은 방향 반복
- 한두 해만 좋아진 결과가 아닐 것
- 기존 후보 priority보다 독립적인 추가정보가 있을 것
- MDD 또는 자본 효율 중 하나를 의미 있게 개선할 것

을 만족해야 한다.

그때도 처음에는 `매수 필터`가 아니라 **보조 우선순위**로만 사용한다.

1. Forward V1/V2는 계속 관찰
