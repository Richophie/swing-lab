# 오늘의 스윙 — 다음 연구·검증 로드맵

기준일: 2026-08-14

이 문서는 현재까지 구축한 스캔·백테스트·Paper/Forward 구조를 바탕으로, **백테스트에서 좋아 보이는 전략을 실제 매매 후보 시스템으로 끌어올리기 위해 앞으로 무엇을 어떤 순서로 검증할지**를 고정한다.

핵심 원칙은 하나다.

> **좋아 보이는 백테스트를 더 예쁘게 만드는 것이 아니라, 좋아 보이는 전략이 우연인지 아닌지를 계속 공격적으로 검증한다.**

---

## 1. 현재 진행 방식에 대한 평가

현재 방향은 유지한다.

잘한 점:

- 라이브와 백테스트의 전략 규칙을 canonical rule로 통합했다.
- 수수료·슬리피지·스프레드·갭·다음 세션 진입을 모델링했다.
- 300만원 유한계좌, 위험예산, 동시보유 제한, 포지션 비중을 반영했다.
- 같은 종목의 동시 중복 포지션을 막았다.
- Backtrader 독립 실행엔진과 결과를 비교했다.
- 장중 후보 / 마감 확정 추천 / 가상계좌 / 자동 Forward 연구를 분리했다.
- production baseline을 얼리고 연구전략이 실제 추천/주문 규칙을 자동으로 바꾸지 못하게 했다.
- 자동 optimizer의 OOS 누수를 수정해 TRAIN에서만 후보를 고르고 OOS는 pass/fail 검증에만 사용하도록 했다.
- 돌파·Donchian·SMA 계열을 기존 눌림전략과 섞지 않고 연구전략으로 분리했다.

결론:

> **연구 시스템의 구조는 좋은 편이다. 다만 현재 높은 백테스트 수익률을 실전 기대수익률로 해석하기에는 아직 검증해야 할 핵심 문제가 남아 있다.**

---

## 2. 현재 백테스트 숫자의 해석 규칙

현재 백테스트 결과는 다음 의미로만 사용한다.

- 전략 후보를 찾는 연구용 증거
- 서로 다른 전략 가족의 상대 비교
- 위험·회전율·보유기간·시장국면 특성 파악

현재 단계에서 하지 않는 해석:

- `+199%` 같은 결과를 미래 실전 수익률로 간주하지 않는다.
- 현재 MDD 숫자를 실제 계좌 최대 낙폭과 동일하게 보지 않는다.
- 현재 70/30 OOS 하나를 최종 독립시험이라고 부르지 않는다.
- 현재 살아남은 종목만으로 얻은 10년 결과를 당시 실제 투자 가능 시장 전체의 결과라고 부르지 않는다.

# 3. 앞으로 할 일 — 우선순위

## P0. 현재 V3 전체탐색은 한 번 끝까지 완료

목적: 전략 공간 전체를 계속 미세조정하기 전에 큰 지형을 한 번 확인한다.

현재 탐색 대상:

- 전략 1~5개 조합
- exit 방식
- max hold
- 동시보유 capacity

이 탐색의 목적은 **정확한 숫자 하나를 우승자로 뽑는 것**이 아니다.

찾아야 할 것은 다음과 같은 **전략 가족**이다.

예:

- Donchian 중심
- Donchian + SMA
- Donchian + 확인형 눌림
- 추세 + 눌림 혼합

### V3 이후 금지

- 3.0% → 3.1% → 3.2% 식의 촘촘한 익절 최적화
- 5일 → 6일 → 7일 식으로 결과를 보면서 반복 미세조정
- OOS 결과를 보고 같은 OOS에 맞게 재탐색

## P1. 상위 3~5개 전략 가족만 남기기

V3 결과에서 상위 설정값 하나를 고르지 말고, 반복해서 살아남는 구조를 찾는다.

선정 기준:

- TRAIN 수익성
- OOS pass 여부
- 최근구간 유지 여부
- 거래수 충분성
- Profit Factor
- 기대수익
- 회전율
- 특정 몇 종목/몇 거래에 대한 과도한 의존 여부
- capacity 변화에도 성과가 유지되는지

이 단계에서 사소한 파라미터는 단순화한다.

## P2. 진짜 Mark-to-Market Equity / MDD 구현

현재 가장 우선적으로 보완할 백테스트 정확도 항목.

### 문제

열린 포지션의 평가손익이 매 거래일 종가 기준으로 충분히 자산곡선에 반영되지 않으면, 실제 보유 중 발생한 낙폭이 MDD에서 누락될 수 있다.

### 구현

Replay V2의 future OHLC path를 이용해 매 거래일:

1. 현금 계산
2. 모든 열린 포지션 종가 평가
3. 계좌 Equity 계산
4. 최고 Equity 갱신
5. Drawdown 계산

추가 산출:

- true mark-to-market MDD
- equity curve
- underwater 기간
- 월별 수익률
- 연도별 수익률
- 최악 월
- 연속 손실 기간

### 판단

기존 우수 전략의 MDD가 크게 악화되는지 확인한다.

예:

- 기존 -19% → MTM -21%: 구조 유지 가능
- 기존 -19% → MTM -35~-40%: 전략 평가 재검토

## P3. Survivorship Bias 제거용 Point-in-Time Universe 검증

### 현재 한계

현재 유동성이 좋고 살아남은 종목을 골라 과거 10년으로 되감으면:

- 상장폐지 기업
- 합병/파산 종목
- 과거에는 컸지만 현재는 사라진 종목
- 현재 필터에서 탈락한 과거 구성종목

이 빠질 수 있다.

따라서 현재 결과는:

> **현재 살아남은 유동성 좋은 종목군에서의 역사적 성과**

으로 해석한다.

### 최종 검증 목표

가능한 범위에서:

- 당시 시점별 구성종목
- delisted 포함 데이터
- historical membership 또는 point-in-time universe

를 확보하여 상위 전략 가족을 다시 검증한다.

### 완료 조건

Survivorship-free 데이터에서도 전략 방향성과 핵심 성과가 유지될 것.

# 4. 엄선 필터 설계

엄선은 모든 전략에 같은 점수표를 씌우지 않는다.

## 4-1. 공통 안전필터

전략 종류와 무관하게 최소한으로 적용 가능한 항목:

- 충분한 거래대금/유동성
- 비정상 데이터 및 결측 제거
- 과도한 갭 진입 방지
- STOP 훼손 상태 진입 방지
- 실행비용을 감안한 비현실적 거래 제거
- 동일종목 중복 보유 금지
- 계좌 위험한도
- 이벤트/earnings 위험은 우선 관찰값으로 유지

공통 안전필터는 **좋은 종목을 고르는 점수라기보다 거래 자체가 부적절한 상황을 제거하는 역할**로 제한한다.

---

## 4-2. 전략별 엄선점수

### Donchian / 추세 돌파

후보 feature:

- 55일 고점 돌파 강도
- 200일선 기울기
- 종가의 당일 range 내 위치
- ATR 대비 돌파거리
- 거래량 확인
- 추세 지속기간
- 지나친 gap/chase 여부

주의:

Donchian은 낮은 승률 + 큰 승자 구조일 수 있으므로 눌림전략용 필터를 그대로 적용하지 않는다.

### SMA200/20 계열

후보 feature:

- 20DMA / 200DMA 구조
- 200DMA 상승기울기
- 몸통 / ATR
- 이평 돌파의 clean 정도
- 최근 반복 whipsaw 횟수
- 장기 추세 상태

### 거래량 돌파

후보 feature:

- 상대거래량
- 몸통 / ATR
- 종가 위치
- 장기 추세
- 갭 과열 여부

### 기존 눌림 / 확인형 / 모멘텀

기존 구조를 최대한 유지:

- S score
- 수급
- precise RR
- 시장 상태
- entry viability
- elite score
- 반전/모멘텀 개선 feature

---

## 4-3. 전략 간 절대점수 직접 비교 금지

예:

- Donchian 82점
- 눌림반등 82점

을 같은 품질이라고 가정하지 않는다.

각 전략 내부에서 TRAIN 구간을 기준으로 후보를 순위화한다.

추천 실험 강도:

- 원신호: 100%
- 느슨한 엄선: TRAIN 상위 50%
- 일반 엄선: TRAIN 상위 30%
- 강한 엄선: TRAIN 상위 15%

중요:

> 컷은 TRAIN에서 결정하고 이후 OOS에서는 고정한다.

73/74/75/76점처럼 촘촘한 threshold search는 하지 않는다.

# 5. 검증 방법 강화

## P4. 단일 70/30 외에 Walk-Forward 추가

한 번의 70/30 분할만으로 판단하지 않는다.

예시:

- 과거 일정 기간 TRAIN
- 다음 기간 TEST
- 창을 앞으로 이동
- 반복

확인할 것:

- 여러 시장국면에서 성과 유지
- 최근에만 잘 되는 전략인지
- 특정 한 구간이 전체 결과를 끌어올리는지
- TRAIN과 TEST 성과 괴리

---

## P5. 반복탐색 과적합 진단

자동 optimizer가 수많은 조합을 탐색하므로, 최고 백테스트 하나만 보는 방식은 금지한다.

추가할 진단 후보:

- PBO (Probability of Backtest Overfitting)
- Deflated Sharpe Ratio
- parameter neighborhood stability
- top-N 후보의 성과 분산
- 전략별 leave-one-symbol-out
- top trade concentration

목표:

> 최고점 하나가 아니라 주변 설정도 비슷하게 잘 되는 넓은 plateau를 찾는다.

# 6. 새로운 독립 시험지 만들기

현재 역사 데이터 전체는 앞으로 **Development Dataset**으로 취급한다.

최종 독립 검증은 둘 중 하나 이상을 사용한다.

1. 새로 확보한 point-in-time / survivorship-free 역사 데이터
2. 2026-08-14 이후 실제 Forward Shadow 데이터

# 7. 최종 후보 규칙 동결

상위 후보가 정해지면 더 이상 과거 결과를 보고 계속 규칙을 바꾸지 않는다.

- 엄선 cutoff

버전 예시:

`challenger-v1.0-YYYY-MM-DD`

# 8. Forward Shadow 검증

최종 후보는 실제 주문 없이 독립 계좌에서 자동 운용한다.

Forward에서 기록:

- 실제 신호 시각
- 당시 데이터 snapshot
- 추천 BUY / STOP / exit rule
- 실제 확보 가능한 다음 세션 가격
- 예상 vs 실제 slippage
- 보유 중 mark-to-market
- 실현 P&L
- MDD
- 승률
- PF
- expectancy
- 전략별 결과
- 시장상태별 결과
- event-risk별 결과

기존 원칙 유지:

- 종료 30건 전 production 튜닝 금지
- 30~49건: 가설 검토만
- 50건부터 정식 Forward Review 가능

가능하면 최종 production 승격 전에는 전략별/전체 표본을 더 많이 축적한다.

# 9. Production 승격 조건

자동 optimizer 1등이라는 이유만으로 production에 반영하지 않는다.

후보는 최소 다음을 통과해야 한다.

### 역사 검증

- TRAIN 양수
- OOS 양수 또는 명확한 위험개선
- Walk-forward 다수 구간 생존
- 최근 구간 붕괴 없음
- MTM MDD 허용범위
- 거래수 충분
- 특정 소수 종목/거래에 과도하게 의존하지 않음

### 데이터 견고성

- survivorship-free / point-in-time 재검증 가능 시 통과
- lookahead 없음
- 동일 시점에 알 수 없는 feature 사용 없음

### 실행 견고성

- 비용·슬리피지 포함
- gap 처리
- STOP/TARGET intraday 순서 보수적 처리
- Paper/Forward 결과가 백테스트와 크게 괴리하지 않음

### 실전 검증

- Frozen Forward 후보가 최소 표본을 축적
- 기존 champion 대비 위험조정 성과 또는 안정성 개선

최종 승격은:

> **Research Challenger → Validation Passed → Frozen Forward → Champion Promotion**

순서를 지킨다.

# 10. 절대 하지 않을 것

- OOS 결과를 보고 같은 OOS에서 다시 최적화
- 수익률 하나만 보고 전략 승격
- 현재 살아남은 종목만으로 얻은 역사결과를 unbiased 결과라고 주장
- 전략별 성격이 다른데 동일한 엄선점수 강제
- 점수 cutoff를 1점 단위로 무한 탐색
- 자동 optimizer가 production 코드를 직접 수정
- Forward 성적이 나쁠 때 과거 기록을 재작성
- 실제 주문 권한과 연구 프로세스를 연결

## 최종 판단 기준

우리가 원하는 것은 백테스트 1위 전략이 아니다.

원하는 전략은:

- 여러 시기에서 살아남고
- 여러 종목에서 작동하고
- 비용을 넣어도 남고
- 극단적인 파라미터 하나에 의존하지 않고
- 실제 Forward에서도 비슷한 행동을 보이며
- 계좌가 감당 가능한 MDD 안에서
- 반복해서 기대수익을 만들어내는 전략이다.

이 조건을 만족하기 전까지 모든 높은 백테스트 수익률은 **후보 성적**으로만 취급한다.
