# Swing Lab Forward Research Baseline v1

> 고정일: 2026-08-13  
> 식별자: `baseline-v1.0-2026-08-13`  
> 목적: 실제 공개된 마감 확정 추천을 이후 데이터로 검증하기 위한 변경 불가 비교 기준

## 1. Baseline v1

Baseline v1은 2026-08-13 시점의 공개 전략과 실행 규칙을 고정한다.

- 공개 전략
  - `confirmed_pullback`
  - `rsi2_trend_reversion`
  - `momentum_pullback`
- 전략 S 기준: `85`
- 자동연구 초기자금: 계좌별 `3,000,000 KRW`
- 최대 동시 포지션: 계좌별 `3`
- 거래당 risk budget: equity의 `1%`
- 종목당 최대 노출: equity의 `40%`
- 동일 날짜 슬롯 경쟁: 추천 당시 ex-ante gross risk/reward 우선
- STOP 최소 거리: `1.5 ATR`
- 다음 시가형 gap guard: `max(0.75 ATR, BUY 기준가의 1%)`
- 비용 가정
  - 매수/매도 수수료 각 `0.10%`
  - slippage `5 bps`
  - half spread `2.5 bps`

실제 상수는 `baseline_rules.py`의 `baseline_snapshot()`이 권위 원본이다.

## 2. 공식 추천 데이터 고정

미국장 마감 후 16:05 America/New_York 이후 확정된 `official_public` 추천만 자동연구의 입력으로 사용한다.

주문 생성 당시 다음 정보를 함께 저장한다.

- baseline version
- app version / core version
- 전략 ID / 점수
- 추천 당시 risk/reward
- 추천 당시 시장 상태
- 실적 이벤트 위험 스냅샷
- BUY / TARGET / STOP
- ATR 및 gap guard

이후 엔진 버전이나 전략 수치가 바뀌더라도 기존 거래의 당시 조건을 소급 변경하지 않는다.

## 3. A/B 자동연구 계좌

두 연구 계좌는 각각 독립적인 300만원 계좌이며 서로 슬롯/현금을 공유하지 않는다.

### A · 다음 시가형

- 마감 확정 추천을 다음 거래일 시가에 평가한다.
- 시가가 BUY 기준 ± canonical gap guard 안이면 가상체결한다.
- 기존 Paper Broker의 보수적 실행비용을 적용한다.

목적: 현재 Swing Lab의 기존 자동연구 실행방식을 Baseline 비교군으로 보존한다.

### B · BUY 상단 이하형

BUY 범위를 좁은 '박스'로 해석하지 않는다.

- `BUY high` = 새 포지션을 만들 수 있는 **최대 허용 매수가**
- 다음 거래일이 BUY high보다 낮게 시작하면 더 좋은 가격이므로 즉시 가상체결한다.
- BUY high보다 위에서 시작하면 장중 BUY high까지 하락할 때 기다린다.
- BUY low보다 더 낮아도 STOP 위라면 더 좋은 진입가격으로 인정한다.
- 이미 STOP 이하에서 시작하면 매매 가설이 깨진 것으로 보고 새 포지션을 만들지 않는다.
- 다음 거래일 안에 허용가격이 오지 않으면 해당 주문은 취소한다.

목적: '추천 다음날 실제로 더 좋은 눌림 가격을 기다리는 방식'이 다음 시가 즉시진입보다 우월한지 forward 데이터로 비교한다.

## 4. STOP / TARGET 선후 판정

일봉 OHLC만으로 같은 날 STOP과 TARGET을 모두 터치했을 때 순서를 알 수 없는 문제가 있다.

앞으로의 판정 순서:

1. 해당 거래일의 1분봉을 확보한다.
2. 시간순으로 TARGET/STOP 중 먼저 닿은 레벨을 결과로 사용한다.
3. 같은 1분봉 안에서 양쪽을 모두 찍어 정확한 틱 순서를 알 수 없는 경우에만 STOP 우선으로 보수 처리한다.
4. 1분봉을 확보하지 못한 경우에도 기존처럼 STOP 우선 fallback을 사용하되 `daily_ambiguous_stop_fallback`으로 품질을 기록한다.

공식 추천 기록의 기존 모호한 STOP 결과도 최근 1분봉을 확보할 수 있는 범위에서는 `intraday_outcome_repair.py`가 재확인한다.

## 5. 표본 게이트

Forward 데이터가 적을 때 성과를 보고 전략 수치를 즉흥적으로 수정하지 않는다.

- 종료 거래 `0~29건`: **표본 축적중**
  - production 전략 수치 튜닝 금지
- 종료 거래 `30~49건`: **1차 가설검토**
  - 조건별 차이를 관찰하고 가설만 기록
  - production 승격/교체는 보류
- 종료 거래 `50건 이상`: **정식 Forward Review 가능**
  - A/B, 전략별, 시장상태별, RR별, 보유기간별 결과를 함께 검토

A와 B 중 어느 한쪽이라도 아직 표본 게이트에 걸려 있으면 production tuning lock은 유지한다.

## 6. 연구소 성적판

`자동거래연구소` 화면은 다음 정보를 A/B 별로 비교한다.

- 총자산
- 실현손익
- 승률
- 종료 거래 수
- 진행 주문/포지션
- 실현자산 기준 MDD
- A/B 자산곡선
- 전략별 성과
- 시장상태별 성과
- 손익비 구간별 성과
- 종료 사유별 성과
- 보유기간별 성과
- 실행 판정 품질별 성과

이 화면은 연구/관찰 전용이며 수동 주문취소·수동매도 버튼을 제공하지 않는다.

## 7. 사용자 가상계좌와의 분리

`가상계좌`는 자동연구소가 아니다.

- 사용자가 `가상매수`를 누르면 최근 확보 가능한 시장가격으로 즉시 가상체결한다.
- 시장이 닫혀 있으면 화면에 표시된 최근 1분/일봉 기준가를 사용하고 기준시각을 저장한다.
- 체결 직후부터 현재가 기준 평가손익을 표시한다.
- 사용자가 직접 가상매도할 수 있다.
- 이 성과는 사용자의 선택편향이 포함되므로 자동연구소의 전략 성과와 섞지 않는다.

## 8. 분할매수 / 분할매도

Baseline v1에는 분할매수·분할매도를 넣지 않는다.

이유:

- 현재 핵심 질문은 신호의 질과 진입방식(A/B)의 차이다.
- 동시에 분할규칙까지 바꾸면 어떤 요소가 성과를 개선했는지 분리하기 어렵다.
- 표본이 충분히 쌓인 뒤 별도 실험군으로 검증한다.

향후 후보 실험:

- C: BUY 이하 50% + 추가 하락 시 50% 분할매수
- D: TARGET 이전 급등 시 50% 익절 + 잔여분 추적청산

단, 이들은 Baseline A/B와 별도 계좌 또는 동일 신호의 shadow replay로만 비교하고 바로 production 규칙에 넣지 않는다.

## 9. 안전 경계

- `live_trading_enabled = false`
- 실제 증권사 주문 전송 없음
- 자동연구소에는 사람의 수동매도/취소 기능 없음
- brokerage adapter가 생기더라도 별도의 검증/승인 단계 없이는 live 주문을 허용하지 않는다.
